# Publishing plan — `3d-printer-models` → Cults3D, MyMiniFactory, Thingiverse

Implementation plan and work checklist. **No code until this is agreed.**

---

## 1. What exists today

| | |
|---|---|
| Models | 14 directories, ~39 releasable part STLs (coupons excluded) |
| Per model | parametric `.scad`, `README.md` (parts table, hardware, print settings, parameters), Blender `preview.png` |
| Enforcement | `tools/check_catalog.py` fails a PR if a model dir lacks README / preview / catalog row |
| Build | `tools/build_release.sh <slug> dist` → STL per top-level `.scad`, validated by `validate_stl.py`, one Blender PNG each |
| Release | tag `<slug>/vX.Y.Z` → `release.yml` renders + `gh release create` with `dist/*` attached |
| License | models CC BY-NC 4.0; `lib/` + `tools/` MIT (SPDX headers) |
| Largest STL | ~2 MB — far under every platform limit (MMF 100 MB, Thingiverse ~250 MB) |

**The release pipeline is already the right shape.** Cults3D's `createCreation` takes *public HTTPS URLs* and fetches server-side rather than accepting multipart uploads — GitHub Release asset URLs satisfy that exactly. The normally-awkward integration is the one already solved.

## 2. What's missing

1. **No machine-readable metadata.** READMEs are prose. Title, summary, tags, and per-platform category can't be derived reliably.
2. **No printed photos.** `preview.png` is a Blender render. Not all models are printed yet.
3. **No description format.** READMEs use tables and relative image links; no platform renders that well.
4. **License doesn't map to Thingiverse.** Their enum is `cc, cc-sa, cc-nd, cc-nc-sa, cc-nc-nd, pd0, gpl, lgpl, bsd` — **no plain `cc-nc`**.
5. **No publish state.** Nothing records which platform holds which model at which version → create-vs-update is undecidable.

## 3. Decisions needed before implementation

### D1 — Thingiverse license
CC BY-NC 4.0 is not in their enum. Options:

- **(a) Spike it first.** Their changelog claims license options were added since the docs were written; the enum may be stale. Verify empirically against the live API before deciding.
- **(b) Publish to Thingiverse as `cc-nc-sa`.** Adds ShareAlike — more restrictive on remixers than you chose.
- **(c) `cc-nc-nd`.** Bans derivatives; contradicts the point of shipping parametric source.
- **(d) Skip Thingiverse** if no faithful option exists.

*Recommendation: (a), fall back to (b).* Do not silently publish under different terms than the repo states.

### D2 — Where printed photos live
- **Commit to `<model>/photos/`** — consistent with committing `preview.png`, renders in the README, simple. Cost: ~30–50 MB repo growth at 2–4 JPEGs per model. Mitigate with a lint on file size (e.g. ≤1.5 MB, long edge ≤2400 px).
- **Attach to the GitHub Release instead** — keeps the repo lean and gives Cults3D public URLs for free, but photos stop being visible in the repo and can't be validated pre-tag.

*Recommendation: commit, with a size lint.*

### D3 — Thingiverse as a separate tool (ToS)
Thingiverse API ToS §3.f: *"Your Application shall not allow you or your Users to upload any User Content to any other 3D design sharing community website or 3D design sharing platform."* §4.e.xi additionally bars posts not initiated by a user.

A single `tools/publish` that targets all three is plainly one Application that does the prohibited thing. Options:

- **(a) Separate repo**, e.g. `thingiverse-publisher`, its own OAuth app, manifest schema vendored. Cleanest reading of §3.f.
- **(b) Same repo, hard-separated entry point** — `tools/publish_thingiverse.py`, no shared invocation path, never in the same command or workflow. Cheaper; relies on "Application" meaning the registered OAuth app, not the repo.

*Recommendation: (b) to start, (a) if you ever make it public.* Either way: **Thingiverse publishing is manual-invoke only, never CI-triggered.** Cults3D and MMF may be CI-triggered.

### D4 — AI disclosure per platform
No platform's written policy reaches a human authoring parametric OpenSCAD with an AI coding assistant. Their flags mean *geometry or preview images generated by AI*, which yours are not.

- Cults3D `madeWithAi`: **false**
- Thingiverse AI tag: **not set**
- Repo README AI-assistance line: **keep in the repo**, but do not copy verbatim into platform descriptions. Descriptions instead link the GitHub repo and note the source is OpenSCAD with full version history — stronger provenance evidence than a disclaimer, and not misreadable by a skimming reviewer.

Make this an explicit `ai.disclose` field in the manifest so it's a recorded choice, not an implicit one.

### D5 — One listing per model directory
14 listings, each carrying that model's full part set. Coupons stay excluded, matching `build_release.sh`. Alternative (a listing per part) would trip MakerWorld-style "improper split upload" rules elsewhere and fragments the catalog. *Recommendation: one per directory.*

## 4. Design

```
tools/publish/
  __init__.py
  manifest.py       # load + validate publish.yaml, dataclasses
  describe.py       # README.md -> per-platform description
  licenses.py       # CC BY-NC 4.0 -> per-platform representation
  state.py          # read/write .publish/state.json
  release.py        # resolve GitHub Release assets for <slug>/vX.Y.Z
  platforms/
    base.py         # Publisher protocol: create(), update(), verify()
    cults3d.py
    myminifactory.py
  cli.py            # publish <slug> --platform ... --dry-run
tools/publish_thingiverse.py   # deliberately separate entry point (D3)
```

### Per-model manifest — `<model>/publish.yaml`

```yaml
title: Stand cable clamp
summary: >-
  Wingnut clamp for round stand poles with slide-on cable heads
  (hook / clip / comb / velcro).
tags: [cable-management, stand, clamp, parametric, openscad, gridfinity]
categories:
  cults3d:        { id: "...", sub: ["..."] }
  myminifactory:  tags-only        # MMF API exposes no category field
  thingiverse:    "3D Printer Accessories"
printed: true
photos:
  - photos/clamp-on-pole.jpg
  - photos/heads.jpg
ai:
  disclose: link-repo              # never `verbatim-readme`
platforms: [cults3d, myminifactory]   # thingiverse added per-model, opt-in
```

Validated by an extended `check_catalog.py` — same philosophy as today, no exemption list.

### Publish state — `.publish/state.json` (committed)

```json
{"stand-cable-clamp": {
   "cults3d":       {"remote_id": "...", "url": "...", "version": "v1.0.0"},
   "myminifactory": {"remote_id": "...", "url": "...", "version": "v1.0.0"}}}
```

Drives create-vs-update and makes "what's published where" a diffable fact.

### Description rendering
`README.md` → per-platform text. Strip the H1 (goes to the title field), drop relative image links, flatten tables to labelled lines, append a footer with source repo link, license, and version. Golden-file tested per platform.

### Publish gate
`printed: true` **and** at least one photo present, or the publisher refuses. Same enforcement pattern as `check_catalog.py`, extended to publishing. A model can be tagged and released on GitHub without being publishable — those are separate gates on purpose.

## 5. Work checklist

### Phase 0 — Spikes *(do first; cheap, and they can invalidate later phases)*
- [ ] `S1` Thingiverse: confirm live license enum — does a plain `cc-nc` exist? Resolves **D1**
- [ ] `S2` Thingiverse: confirm which upload path works (OpenAPI marks `finalize` deprecated while the upload guide documents it as canonical) and the real file-size cap
- [ ] `S3` Cults3D: confirm a CC BY-NC `licenseCode` exists for a **free** listing, and confirm `tagNames` is accepted
- [ ] `S4` Cults3D: confirm server-side fetch works against a GitHub Release asset URL
- [ ] `S5` MMF: confirm the `licenses[]` boolean flags that faithfully represent CC BY-NC, and confirm undocumented rate limits by observation
- [ ] `S6` Register OAuth apps: MMF (self-serve), Thingiverse (private app, stays under the 10-user cap → no review queue). Cults3D API key is self-serve

### Phase 1 — Manifest + validation
- [ ] Define `publish.yaml` schema; `manifest.py` loader with typed errors
- [ ] Extend `check_catalog.py`: manifest present, parses, required fields, photo paths resolve, photo size lint
- [ ] Author manifests for all 14 models
- [ ] Tests: valid/invalid manifests, missing fields, bad photo paths, size lint
- [ ] `feat/publish-manifest-schema`

### Phase 2 — Description renderer + license mapping
- [ ] `describe.py`: strip H1, drop relative images, flatten tables, append footer
- [ ] Per-platform variants (markdown vs plain)
- [ ] `licenses.py`: CC BY-NC 4.0 → Cults3D code / MMF flags / Thingiverse enum (per **D1**)
- [ ] Tests: golden files for 3 representative models × 3 platforms; license mapping table
- [ ] `feat/publish-description-renderer`

### Phase 3 — Cults3D publisher
- [ ] `release.py`: resolve Release assets for a tag via `gh` / GitHub API
- [ ] `createCreation` + `updateCreation`; `createChangeNotification` on version bump
- [ ] `state.py` read/write; idempotent re-run
- [ ] `--dry-run` prints the exact mutation without sending
- [ ] Tests: recorded-HTTP fakes, no live calls in CI
- [ ] `feat/cults3d-publisher`

### Phase 4 — MyMiniFactory publisher
- [ ] OAuth2 flow + token refresh
- [ ] 3-step upload: `POST /object` → `POST /file?upload_id` → poll `upload_status`
- [ ] Image upload; conservative backoff (rate limits undocumented)
- [ ] Surface curation/approval state back into `state.json`
- [ ] Tests: recorded-HTTP fakes, upload-status polling, backoff
- [ ] `feat/myminifactory-publisher`

### Phase 5 — Photo gate + first live publish
- [ ] Photo requirement enforced in the publisher, not just the linter
- [ ] Print + photograph **one** model end to end
- [ ] Publish that one model to Cults3D and MMF; verify rendering, tags, license, links
- [ ] Fix whatever the real API rejects *(expect surprises here)*
- [ ] `feat/publish-photo-gate`

### Phase 6 — Thingiverse *(separate entry point, manual invoke only)*
- [ ] `tools/publish_thingiverse.py`, separate OAuth app, no shared invocation path
- [ ] `POST /things` → presigned file upload → `POST /publish`
- [ ] Respect 300 req / 5 min; never called from CI
- [ ] Tests: recorded-HTTP fakes
- [ ] `feat/thingiverse-publisher`

### Phase 7 — Rollout
- [ ] Print + photograph remaining models (**the actual bottleneck — not automatable**)
- [ ] Publish in small batches, not all 14 at once
- [ ] Optional: `workflow_dispatch` job for Cults3D + MMF on an existing tag. **Thingiverse excluded from CI by design**

## 7. Risks

| Risk | Mitigation |
|---|---|
| Thingiverse has no faithful CC BY-NC option | Spike `S1` first; skip Thingiverse rather than misstate terms |
| Thingiverse upload path ambiguity (docs contradict spec) | Spike `S2` before Phase 6 |
| MMF curation rejects a listing | Publish one model first; treat approval state as data, not an error |
| MMF rate limits undocumented | Conservative backoff, serialize uploads |
| Repo growth from photos | Size lint; revisit **D2** if it bites |
| Discretionary AI review, despite policy not reaching parametric CAD | Link the repo and its history in every description; don't set AI flags that would misdescribe the work |
